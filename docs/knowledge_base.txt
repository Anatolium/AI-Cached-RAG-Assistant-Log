## 2. Векторные базы данных и эмбеддинги

Векторные базы данных — специализированные системы хранения данных, оптимизированные для работы с векторными представлениями.

Эмбеддинги — это числовые векторные представления объектов.

Эмбеддинги могут представлять текст, изображения, аудио и другие данные.

Каждый эмбеддинг состоит из набора числовых значений.

Размерность эмбеддинга определяется используемой моделью.

Семантически похожие объекты располагаются близко друг к другу в векторном пространстве.

Векторный поиск позволяет находить объекты по смысловому сходству.

Косинусное сходство используется для сравнения направлений векторов.

Евклидово расстояние измеряет расстояние между точками в пространстве.

Dot product — скалярное произведение двух векторов.

ChromaDB — открытая векторная база данных для AI-приложений.

ChromaDB поддерживает хранение эмбеддингов и метаданных.

ChromaDB может использоваться для построения RAG-систем.

ChromaDB поддерживает локальное и клиент-серверное использование.

FAISS — библиотека для эффективного поиска похожих векторов.

FAISS разработана компанией Meta.

Qdrant — специализированная векторная база данных.

Milvus предназначена для хранения и поиска больших объемов векторов.

Pinecone — управляемая облачная векторная база данных.

Weaviate — платформа для хранения и поиска векторных данных.

PostgreSQL с расширением pgvector поддерживает работу с векторами.

Векторные базы данных могут хранить текстовые фрагменты вместе с эмбеддингами.

Метаданные позволяют фильтровать результаты векторного поиска.

Индексирование ускоряет поиск ближайших векторов.

HNSW — алгоритм приближенного поиска ближайших соседей.

ANN означает Approximate Nearest Neighbors.

Точный поиск ближайших соседей может быть затратным на больших объемах данных.

Векторный поиск применяется в поисковых системах, рекомендациях и AI-ассистентах.

## 3. Модели эмбеддингов

Модель эмбеддингов преобразует исходные данные в числовые векторы.

Текстовые эмбеддинги отражают семантическое содержание текста.

Одинаковые по смыслу фразы могут иметь близкие эмбеддинги.

Модели эмбеддингов используются для семантического поиска.

OpenAI предоставляет модели text-embedding-3-small и text-embedding-3-large.

text-embedding-3-small предназначена для эффективного создания текстовых эмбеддингов.

text-embedding-3-large обеспечивает более высокую размерность и потенциально лучшее качество представлений.

Модель эмбеддингов и языковая модель выполняют разные задачи.

Эмбеддинг не является готовым текстовым ответом.

Модели эмбеддингов могут поддерживать несколько языков.

Качество поиска зависит от соответствия модели предметной области и языку документов.

При выборе модели учитывают качество, скорость и стоимость вычислений.

Для построения векторной базы необходимо использовать совместимые эмбеддинги запросов и документов.

Смена модели эмбеддингов может потребовать повторной индексации базы.

Размерность вектора должна соответствовать требованиям выбранного индекса.

Эмбеддинги используются для поиска похожих документов и изображений.

## 4. Машинное обучение

Машинное обучение (Machine Learning) — подраздел искусственного интеллекта.

Машинное обучение изучает алгоритмы, позволяющие компьютерам выявлять закономерности в данных.

Модель машинного обучения обучается на примерах.

Обученная модель может делать прогнозы на новых данных.

Обучение с учителем использует размеченные данные.

В обучении с учителем каждому примеру соответствует известная целевая переменная.

Классификация относится к задачам обучения с учителем.

Регрессия используется для прогнозирования числовых значений.

Пример классификации — определение категории входящего письма.

Пример регрессии — прогнозирование стоимости недвижимости.

Обучение без учителя использует неразмеченные данные.

Кластеризация позволяет группировать похожие объекты.

K-means — популярный алгоритм кластеризации.

Обнаружение аномалий помогает находить необычные события и значения.

Обучение с подкреплением основано на взаимодействии агента со средой.

Агент получает награды или штрафы за свои действия.

Обучение с подкреплением применяется в робототехнике и игровых системах.

Датасет — набор данных для обучения или оценки модели.

Обучающая выборка используется для настройки параметров модели.

Валидационная выборка применяется для настройки гиперпараметров.

Тестовая выборка используется для итоговой оценки качества модели.

Переобучение возникает, когда модель слишком хорошо запоминает обучающие данные.

Недообучение возникает, когда модель недостаточно хорошо выявляет закономерности.

Регуляризация помогает уменьшить риск переобучения.

Точность классификации называется Accuracy.

Precision показывает долю правильных положительных предсказаний.

Recall показывает долю найденных положительных примеров.

F1-score представляет собой гармоническое среднее Precision и Recall.

## 5. Нейронные сети и глубокое обучение

Нейронная сеть — вычислительная модель, состоящая из взаимосвязанных искусственных нейронов.

Искусственные нейронные сети вдохновлены принципами работы биологических нейронных систем.

Нейронная сеть состоит из слоев.

Основные типы слоев — входной, скрытые и выходной.

Каждый нейрон получает входные значения и вычисляет результат.

Веса определяют влияние входных сигналов на результат нейрона.

Функция активации добавляет нелинейность в вычисления нейронной сети.

ReLU — распространенная функция активации.

Sigmoid преобразует значения в диапазон от нуля до единицы.

Softmax используется для преобразования выходов в вероятностное распределение.

Глубокое обучение (Deep Learning) использует многослойные нейронные сети.

Обучение нейронных сетей включает настройку весов.

Градиентный спуск используется для минимизации функции потерь.

Backpropagation — алгоритм обратного распространения ошибки.

Эпоха — один полный проход по обучающей выборке.

Batch — часть обучающих данных, обрабатываемая за один шаг.

Learning rate определяет размер шага при обновлении параметров.

GPU ускоряет обучение нейронных сетей за счет параллельных вычислений.

CUDA — платформа NVIDIA для параллельных вычислений на GPU.

PyTorch — популярный фреймворк глубокого обучения.

TensorFlow — библиотека для создания и обучения нейронных сетей.

Примеры применения ИИ — распознавание изображений, обработка речи и анализ текста.

Генеративный искусственный интеллект создает новый контент на основе полученных данных и инструкций.

Большая языковая модель (Large Language Model, LLM) — нейронная сеть, обученная работать с языком.

LLM может генерировать текст, отвечать на вопросы и анализировать информацию.

## 7. Промпт-инжиниринг

Промпт-инжиниринг — практика разработки эффективных инструкций для языковых моделей.

Промпт — текстовая инструкция или запрос, передаваемый модели.

Качество промпта может существенно влиять на качество ответа.

Хороший промпт содержит понятную задачу и необходимые ограничения.

Роль в промпте задает модели определенную профессиональную или функциональную позицию.

Контекст предоставляет дополнительную информацию для выполнения задачи.

Формат ответа определяет структуру результата.

Ограничения помогают исключить нежелательные действия и результаты.

Zero-shot prompting — выполнение задачи без примеров.

One-shot prompting — выполнение задачи с одним примером.

Few-shot prompting — использование нескольких примеров в промпте.

Chain-of-Thought — подход, связанный с последовательным решением сложных задач.

Step-by-step prompting предлагает выполнять задачу поэтапно.

Role prompting задает модели определенную роль.

Structured prompting использует заранее определенную структуру инструкции.

System prompt задает основные правила поведения модели.

User prompt содержит конкретный запрос пользователя.

Developer instructions задают дополнительные правила работы приложения.

Промпты могут включать примеры желаемого результата.

Для сложных задач полезно разделять инструкции на отдельные этапы.

Промпт должен избегать противоречивых требований.

Промпт-инжиниринг применяется при разработке чат-ботов и AI-агентов.

## 8. RAG — Retrieval-Augmented Generation

RAG — технология генерации ответов с использованием внешних источников знаний.

Полное название RAG — Retrieval-Augmented Generation.

RAG объединяет поиск информации и генерацию текста языковой моделью.

Основная задача RAG — предоставить модели релевантные сведения из внешних документов.

RAG позволяет использовать собственную базу знаний компании.

RAG не требует обязательного переобучения языковой модели на новых документах.

Типичная RAG-система состоит из базы документов, модели эмбеддингов, поискового механизма и LLM.

На этапе индексации документы загружаются в систему.

Документы разбиваются на небольшие фрагменты.

Разбиение документов называется Chunking.

Каждый фрагмент преобразуется в эмбеддинг.

Эмбеддинги сохраняются в векторной базе данных.

При поступлении вопроса пользователя создается эмбеддинг запроса.

По векторному сходству система находит подходящие фрагменты.

Найденные фрагменты передаются языковой модели в качестве контекста.

LLM формирует ответ с учетом полученной информации.

Retrieval — этап извлечения релевантной информации.

Generation — этап генерации ответа.

Chunk Size определяет размер фрагментов документа.

Chunk Overlap определяет перекрытие соседних фрагментов.

Перекрытие помогает сохранить контекст на границах фрагментов.

Top-K определяет количество документов или фрагментов, извлекаемых поиском.

Гибридный поиск объединяет семантический и полнотекстовый поиск.

Reranking — повторное ранжирование найденных документов.

Reranker помогает повысить релевантность результатов поиска.

Метаданные позволяют ограничивать поиск по категориям и другим параметрам.

Качество RAG зависит от качества исходных документов.

Плохое разбиение документов может ухудшить качество ответов.

RAG широко применяется в корпоративных AI-ассистентах.

## 9. AI-агенты

AI-агент — программная система, использующая искусственный интеллект для выполнения задач.

AI-агент может анализировать запросы и выбирать последовательность действий.

В отличие от обычного чат-бота агент может самостоятельно вызывать инструменты.

Инструменты агента называются Tools.

Инструментом может быть API, база данных или функция программы.

Агент может использовать веб-поиск для получения актуальной информации.

Агент может обращаться к CRM-системе.

Агент может создавать документы и обрабатывать файлы.

Агент может выполнять последовательность связанных операций.

LLM часто используется в качестве механизма принятия решений агентом.

Память агента позволяет сохранять информацию между этапами работы.

Краткосрочная память хранит данные текущего взаимодействия.

Долгосрочная память предназначена для сохранения информации на более продолжительное время.

Планирование позволяет агенту разбивать сложную задачу на этапы.

Многоагентная система состоит из нескольких взаимодействующих AI-агентов.

Разные агенты могут специализироваться на отдельных задачах.

Один агент может искать информацию, другой — анализировать ее.

Третий агент может проверять результаты работы предыдущих агентов.

Оркестратор управляет взаимодействием между агентами.

LangGraph позволяет создавать управляемые графы выполнения AI-процессов.

Автономность агента может ограничиваться правилами безопасности.

Для критически важных операций желательно предусматривать подтверждение человека.

Human-in-the-loop означает участие человека в процессе принятия решений.

AI-агенты применяются для автоматизации бизнес-процессов.

## 11. API и интеграции

API — программный интерфейс взаимодействия между приложениями.

API позволяет одной программе использовать функции другой программы.

REST API — архитектурный подход к построению веб-интерфейсов.

HTTP — протокол передачи данных в интернете.

HTTPS — защищенная версия HTTP с использованием шифрования.

GET обычно используется для получения данных.

POST обычно используется для отправки данных или создания ресурсов.

PUT используется для полной замены ресурса.

PATCH используется для частичного изменения ресурса.

DELETE используется для удаления ресурса.

JSON — популярный формат обмена структурированными данными.

JSON состоит из пар ключ-значение, массивов и вложенных объектов.

API-ключ используется для идентификации и авторизации клиента.

API-ключ необходимо хранить в защищенном месте.

Bearer Token часто применяется для авторизации API-запросов.

OAuth 2.0 — стандарт делегированной авторизации.

Webhook позволяет системе отправлять уведомления другой системе при наступлении события.

Endpoint — конкретный адрес API-метода или ресурса.

Request — запрос клиента к серверу.

Response — ответ сервера на запрос.

HTTP-код 200 означает успешное выполнение запроса.

HTTP-код 201 означает успешное создание ресурса.

HTTP-код 400 обычно указывает на некорректный запрос.

HTTP-код 401 указывает на отсутствие действительной аутентификации.

HTTP-код 403 означает отсутствие необходимых прав доступа.

HTTP-код 404 означает, что ресурс не найден.

HTTP-код 429 означает превышение допустимого количества запросов.

HTTP-код 500 указывает на внутреннюю ошибку сервера.

Rate Limit ограничивает количество запросов к API за определенное время.

Timeout определяет максимальное время ожидания ответа.

## 12. Базы данных

База данных — организованное хранилище структурированной или неструктурированной информации.

СУБД — система управления базами данных.

SQL — язык запросов для работы с реляционными базами данных.

PostgreSQL — популярная реляционная СУБД с открытым исходным кодом.

MySQL — широко используемая реляционная СУБД.

SQLite — компактная встроенная реляционная база данных.

SQLite не требует отдельного серверного процесса.

MongoDB — документоориентированная NoSQL-база данных.

Redis — хранилище данных типа ключ-значение, часто используемое в памяти.

Реляционная база данных хранит информацию в таблицах.

Таблица состоит из строк и столбцов.

Первичный ключ уникально идентифицирует запись.

Внешний ключ связывает записи разных таблиц.

Индекс ускоряет поиск данных в таблице.

SQL-запрос SELECT используется для получения данных.

SQL-запрос INSERT используется для добавления записей.

SQL-запрос UPDATE изменяет существующие записи.

SQL-запрос DELETE удаляет записи.

JOIN объединяет данные из нескольких таблиц.

Транзакция представляет собой логически завершенную группу операций.

ACID описывает свойства надежных транзакций.

Нормализация помогает уменьшить избыточность данных.

Резервная копия базы данных называется Backup.

Восстановление данных из резервной копии называется Restore.

Git — распределенная система контроля версий.

## 18. Безопасность и защита данных

Кибербезопасность — защита информационных систем от угроз и атак.

Аутентификация подтверждает личность пользователя.

Авторизация определяет права доступа пользователя.

Пароль должен быть достаточно сложным и уникальным.

Хеширование преобразует данные в строку фиксированной длины.

Хеширование паролей используется для безопасного хранения учетных данных.

Для хранения паролей применяются специальные алгоритмы, например Argon2 и bcrypt.

Двухфакторная аутентификация повышает безопасность учетной записи.

Шифрование защищает данные от несанкционированного прочтения.

HTTPS защищает передачу информации между клиентом и сервером.

SQL Injection — атака с внедрением вредоносного SQL-кода.

XSS — атака с внедрением вредоносного клиентского кода.

CSRF — атака с подделкой межсайтовых запросов.

Валидация входных данных помогает предотвращать многие уязвимости.

API-ключи и пароли необходимо хранить в переменных окружения или защищенном хранилище.

Принцип минимальных привилегий ограничивает права пользователей необходимым минимумом.

Резервное копирование помогает восстановить данные после сбоя.

Персональные данные требуют особого внимания при обработке и хранении.

Prompt Injection — попытка изменить поведение языковой модели через вредоносные инструкции.

Защита AI-систем должна учитывать недоверенные документы и пользовательский ввод.
